# Excalidraw Data

## Text Elements
Tech stack ^el1

What it is built with, and why each piece ^el3

🖥️ Frontend ^el6

Vite + React 18 + TypeScript
@xyflow/react draws the graph
dagre lays it out
JetBrains Mono, hash routing, no state
library: App.tsx holds the data
vitest + Testing Library ^el7

⚙️ Backend ^el10

Node 22 + TypeScript
Fastify 5 (REST, validation by hand)
better-sqlite3 (synchronous SQLite)
@fastify/static serves the built UI
vitest + app.inject on :memory: ^el11

🤖 MCP ^el14

stdio MCP server (official SDK + zod)
A thin client over the REST API
esbuild bundles it into one .mjs the
backend serves for download ^el15

🗄️ Data ^el18

One SQLite file in a Docker volume
Idempotent additive migrations at startup
No ORM: plain SQL in app.ts ^el19

🐳 Delivery ^el22

Multi-stage Dockerfile, node:22-alpine
docker compose, config in .env
Makefile for everything else ^el23

REST JSON ^el26

REST + key ^el29

SQL ^el32

Why this stack ^el34

One language everywhere (TypeScript): the
types of the API payloads are mirrored by
hand between packages, and a small team can
touch any part. ^el36

SQLite + better-sqlite3: zero services to
run, one file to back up, fast synchronous
reads for a team-sized dataset. ^el38

No framework on top of Fastify, no ORM, no
state library: fewer moving parts, and
everything fits in a few readable files. ^el40

Constraint: Node 22.12+ (better-sqlite3 segfaults on 20; @fastify/static needs require(esm)). make node installs a private copy if the system has
none. ^el42
